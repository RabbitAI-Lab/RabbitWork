## 1. 三级作用域

```
system（系统管理员）──→ organization（组织管理员）──→ project（项目管理员/成员）
```

- 用户跨组织/项目通过成员关系与用户组获得叠加权限，**权限取并集、禁用取交集**（任一所在组禁用即禁用）
- 多组织策略随产品定位确定（若单组织起步，默认组织由 seed 幂等创建）

## 2. 预置用户组（随认证规格落地）

| 级别 | 组                    | 权限                                                    |
| ---- | --------------------- | ------------------------------------------------------- |
| 系统 | 系统管理员 / 系统成员 | 全量 / 基础只读（组织列表、个人中心）                   |
| 组织 | 组织管理员 / 组织成员 | 组织全量（成员/项目/模板/日志） / 项目列表只读         |
| 项目 | 项目管理员 / 项目成员 | 项目全量 / 业务读写（按各资源默认权限点）               |

预置组权限不可编辑；自定义组在三级各自可建，勾选权限点生成。

## 3. 权限点规范

格式：`{SCOPE}_{RESOURCE}:{ACTION}`，SCOPE ∈ SYSTEM/ORG/PROJECT，ACTION ∈ READ/CREATE/UPDATE/DELETE（域专用动作如 EXECUTE/SHARE 需评审登记）。

登记处于 `packages/shared/permissions.ts`（单一来源；S0 已含系统/组织基线集）。新增权限点规则：**随首份消费它的功能规格评审入库，禁止规格外私用**（`isValidPermission` 辅助校验格式）。

## 4. 检查链

```
请求 → 认证中间件（Session/Token/APIKEY）→ Route Handler 声明权限点（withPermission 包装）
     → 三级取并集判定 → 通过/403(10003)
前端 → 路由守卫（菜单级）+ 按钮级权限控制，权限点清单登录时下发；权限数据未就绪 = 禁止操作（fail-closed）
```

- **APIKEY 与会话用户走同一权限链**（个人 APIKEY ≤5 条）
- 免登录分享路由（/share/*）不走权限链，走独立 share_token 校验 + 过期判断
- 越权访问返回 404（资源不存在或不属于当前项目）与 403（无权限点）区分，防资源枚举

## 5. 数据隔离

- 项目级资源所有查询强制 `project_id` 过滤（服务端守卫 `withProjectScope()` 统一收口，随首个项目级资源落地）
- 组织级资源强制 `org_id`；跨域引用只经 Provider 接口
- 任务中心/日志按用户所在 org/project 范围过滤
- RLS 租户纵深防御为可选增强（引入多租户时按 RabbitAITest INFRA-006 先例：运行时 admin/tenant 双 Prisma 通道），未引入前以应用层 scope 过滤为唯一防线
