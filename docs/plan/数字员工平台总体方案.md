## 一、产品一句话（建议，待评审填定）

> **RabbitWork：把岗位经验流程化的企业数字员工平台——将提示词、技能、知识与工具装配为可对话、可观测、可考核的数字员工，接入组织协作流程持续上岗。**

对标基线：StaffDeck（岗位/员工档案/技能 SOP/知识检索/执行轨迹），差异点：**Agent 运行时不自研，全部委托自部署 AgentScope 智能体服务**；RabbitWork 专注组织管理、员工装配、编排映射与观测考核（控制面）。

## 二、总体架构：控制面 + 运行面

```
┌─────────────────────────────────────────────────────────────┐
│  控制面 RabbitWork（本仓，Next.js 全栈）                      │
│  ├─ UI：员工工作台/会话/知识/观测（React 19 + AntD）          │
│  ├─ API：/api/v1/*（Route Handlers，zod 契约 + RBAC）        │
│  └─ PG（embedded/外接）：组织、员工档案、映射、审计           │
└───────────────┬─────────────────────────────────────────────┘
                │  Provider 适配层（唯一出口，SSE 透传）
                ▼
┌─────────────────────────────────────────────────────────────┐
│  运行面 AgentScope 智能体服务（自部署，不自研）               │
│  agents / sessions(SSE 会话回放/中断) / workspaces /          │
│  environments(sandbox) / files / RAG(可选) / cron 调度        │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 职责切分（最重要的架构决策）

| 职责 | 归属 | 说明 |
| ---- | ---- | ---- |
| 用户/组织/项目、RBAC 三级权限 | RabbitWork | schema.prisma 已有 User/Organization/OrgMember/ProjectMember 基线 |
| 数字员工档案（岗位、人设、能力画像） | RabbitWork | 新建 `staff` 域表；员工 = 档案 + AgentScope agent 的映射 |
| Agent 定义与版本（提示词/system prompt 装配） | **AgentScope**（存量）+ RabbitWork 映射 | 员工档案中的「装配清单」在发布时同步/注册到 AgentScope agent |
| 会话运行、消息流、中断、回放 | **AgentScope** | RabbitWork 只做 SSE 透传 + 审计落库（事件摘要，不镜像全量） |
| 知识库（摄取/切片/检索） | **AgentScope RAG**（S3 评估） | 若实例未启用 knowledge_base_manager，则降级为 AgentScope workspace 文件 + 检索工具 |
| 定时任务 | **AgentScope Cron**（S4 评估） | RabbitWork 侧只存业务级任务定义与运行记录视图 |
| 消息渠道（飞书/微信等） | 预留 | 参照 StaffDeck channels 域，S5+ |
| 观测、审计、用量、反馈分析 | RabbitWork | 运行面事件流订阅采样 + 调用审计 |

**红线**：RabbitWork **不**在自身内实现任何 agent 执行循环/LLM 调用/记忆存储；一切运行能力经 `packages/agentscope-client`（新包）访问，避免与运行面能力重复建设（AGENTS.md 门禁 6：禁止 speculative 功能）。

### 2.2 AgentScope 集成层（首个技术验证目标）

对自部署实例（已实测可用）的初步探明结果：

- **鉴权**：`POST /api/auth/login`（username/password）→ JWT（Bearer），角色 user/admin
- **管理面 `/api/*`**：`sessions`、`workspaces`（含 agentsMd/mcpServers/skills）、`environments`（sandbox）、`files`
- **网关面 `/api/v1/*`**：`agents`（tenant/namespace/agentKey/displayName/version/status）、`sessions`（agentId/bindingId/phase[idle|busy|terminated]/originType）——多租户归属 `user_id` 强制
- 官方文档：[智能体即服务 · 架构](https://docs.agentscope.io/zh/versions/2.0.10/deploy/agent-service)（会话 SSE 事件流扇出、缓冲重放、interrupt、后台任务卸载、Cron、Agent Team）

集成层设计（落地为 `packages/agentscope-client` + `apps/web/src/server/providers/agentscope`）：

1. **契约先行**：Sprint 1 首个任务 = 对实例做一次全量接口探测定型，产出 zod schema（请求/响应/SSE 事件 union）注册进 `packages/shared`，OpenAPI/事件 schema 快照进 CI（门禁 4 遗留项在此一并落地）。
2. **服务账号模型**：RabbitWork 后端持有 AgentScope admin 凭证（env：`AGENTSCOPE_BASE_URL` / `AGENTSCOPE_USERNAME` / `AGENTSCOPE_PASSWORD`）；终端用户**不直接**持有 AgentScope token，所有调用经 RabbitWork BFF（权限点校验 → 映射 → 代理）。
3. **SSE 透传**：会话聊天走 Route Handler 流式转发（`/api/v1/chat/sse`），同时按采样策略把事件摘要写入审计表；断线重连依赖 AgentScope 会话回放缓冲。
4. **映射策略**：`Staff ↔ AgentScope agent(namespace/agentKey)`、`ChatConversation ↔ AgentScope session(originType=chat, originRef=RabbitWork conversationId)`，映射表存 RabbitWork PG，是两侧的唯一关联事实源。
5. **降级与容错**：AgentScope 不可达时 BFF 返回 `503 + AGENTSCOPE_UNAVAILABLE`（api-conventions 错误码分段）；超时/重试策略登记 observability 规范。

## 三、功能域与模块划分

域编号沿用规格文档体系 `docs/sprint-{N}-*/`：

| 域 | 编号前缀 | 核心功能（对标 StaffDeck 形态裁剪） | 阶段 |
| -- | -------- | ------------------------------------ | ---- |
| 系统/认证 | SYS | 登录、用户管理、组织/项目、RBAC 权限点装配 | S1 |
| 数字员工 | STAFF | 员工档案（岗位/工号/头像/人设/能力画像）、装配清单（模型/技能/知识/工具绑定）、发布/下线/版本、员工市场（复用） | S1-S2 |
| 会话工作台 | CHAT | 与数字员工对话（SSE 流式）、会话列表/归档、中断、回放、消息反馈 👍👎 | S1-S2 |
| 知识库 | KNW | 文档上传、知识桶、检索调试、来源引用（视 AgentScope RAG 服务能力定自建/委托） | S3 |
| 技能/SOP | SKILL | 首版：提示词级技能模板 + 员工装配；后续：自然语言蒸馏→结构化 SOP 状态机（节点/条件边/人工节点/子流程嵌套）+ 可视化编辑 + 版本分支（对标 StaffDeck 状态机技能，S4+） | S3-S4 |
| 定时任务 | CRON | 业务级定时触达数字员工、运行记录 | S4 评估 |
| 观测审计 | OBS | 调用轨迹、用量统计（token/次数）、审计日志、反馈分析看板 | S2 起 |
| 消息渠道 | CHNL | 飞书/微信等外部渠道绑定（StaffDeck channels 先例） | S5+ 预留 |

### Sprint 规划建议（每 Sprint 收尾遵循门禁 9：push + 远端 CI 绿）

**Sprint 1 — 打通主链路（最小可用对话）**
1. `INFRA-002 agentscope-adapter`：探测定型契约 + zod schema + OpenAPI 管线 + client 包 + health 探活端点（纯后端，接口契约评审替代高保真）
2. `SYS-001 auth`：登录/登出、会话、当前用户、withPermission 装配（高保真：极简登录页）
3. `STAFF-001 staff-crud`：数字员工档案 CRUD + 发布到 AgentScope（建档→注册 agent→映射落库）
4. `CHAT-001 chat-min`：会话创建 + SSE 对话透传 + 消息渲染（含流式、中断、错误态）
5. 数据模型：`staff` 域表按门禁 3 **一次建齐**（含 KNW/SKILL 预留列）

**Sprint 2 — 工作台完整化**：会话管理（列表/归档/重命名/回放）、员工列表/详情/上下线、消息反馈 👍👎、转人工标记、OBS 最小看板（调用量/成功率/Trace 时间线）

**Sprint 3 — 知识与技能**：KNW-001（文档上传→AgentScope workspace/RAG）、SKILL-001（提示词技能模板 + 员工装配）

**Sprint 4+**：SOP 状态机编排（蒸馏+可视化编辑）、CRON、员工广场（资源复用/复制不动原件）、多员工协作（AgentScope Agent Team，参照 StaffDeck 黑板/竞标模式评估）、CHNL 渠道（飞书/企微/钉钉，入站幂等+出站重试）—— 均先出规格评审再排期。

## 四、数据模型草案（staff 域一次建齐，Sprint 1 定稿）

新增核心表（命名/软删/索引遵循 rules/database.md；全部列含未启用一次建齐）：

```
staffs                 数字员工档案：id/orgId/code(工号)/name/title(岗位)/avatarUrl/persona(人设 jsonb)/
                       capabilityProfile(能力画像 jsonb)/status(DRAFT|PUBLISHED|OFFLINE)/
                       asAgentId/asNamespace/asAgentKey(AgentScope 映射)/asVersion/publishedAt/…
staff_versions         每次发布快照：staffId/version/assemblyJson(装配清单)/promptCompiled
staff_model_bindings   模型绑定（role→model，StaffDeck「按角色绑模型」先例：router/step/response 可各绑不同模型）
staff_resource_bindings 通用资源绑定（StaffDeck AgentResourceBinding 先例：一套表挂 N 类资源）
                       resourceType(SKILL|KNOWLEDGE|TOOL|MCP) + resourceId + paramsJson + enabled
                       —— 替代为每类资源单独建表，扩展新资源类型零 DDL
conversations          会话：id/orgId/staffId/userId/title/status/asSessionId/originRef/lastMessageAt
messages               消息（审计级摘要，非全量镜像）：conversationId/role/content(摘要)/tokenUsage/eventMeta
message_feedback       👍👎 与理由（后续接「演进提案」：反馈→能力改进建议，StaffDeck EvolutionProposal 先例）
skill_templates        技能模板：name/description/kind(PROMPT|SOP)/promptTemplate/sopGraph(jsonb 状态机图)/
                       variablesSchema/version —— SOP 首版仅 PROMPT，状态机编排（节点/条件边/人工节点）为 S4+
audit_logs             操作与调用审计：actor/action/target/reqId/latency/statusCode
```

> 借鉴 StaffDeck 实测经验（68 表落地验证过的模式）：①通用资源绑定表而非每类一张；②按角色绑模型；③反馈→演进提案闭环；④渠道入站幂等/出站重试（CHNL 落地时参考）；⑤开放 API 三级密钥 + scope 子集校验（对外 API 落地时参考）。

与既有 RBAC 基线关系：`staffs.orgId → organizations`；会话隔离按 `orgId + userId`（私域）与项目共享（后续 ProjectMember 扩展）。

## 六、风险与待确认问题（评审议题）

| # | 议题 | 影响 | 建议 |
| - | ---- | ---- | ---- |
| 1 | 实例未暴露公开 OpenAPI 文档（/docs 为 SPA 回退），接口需实测探测定型 | 契约漂移风险 | Sprint 1 首任务做契约快照 + CI 校验；联系部署方确认版本 pin 2.0.10 |
| 2 | AgentScope 实例是否启用 RAG 服务 / Cron | 决定 KNW/CRON 自建 or 委托 | 部署方确认 `create_app` 参数；未启用则 KNW 走 workspace 文件方案 |
| 3 | AgentScope 凭证/模型配置归属：RabbitWork 服务账号代管 vs 每用户独立命名空间 | 多租户隔离设计 | 建议服务账号 + namespace 映射（org→namespace），评审定 |
| 4 | 公网 IP + HTTP 明文 + 弱密码形态的 admin 凭证 | 安全（rules/security） | 至少换 HTTPS/强凭证；凭证只进 env 不入库不进日志 |
| 5 | StaffDeck AGPL-3.0 许可 | 若移植其代码/设计需开源传染 | 只借鉴功能形态与交互，**不复制代码**；设计文档参考不构成衍生作品（评审确认） |
| 6 | embedded-postgres 单机 vs 生产外接 PG | 数据可靠性 | 沿用现有双轨（DATABASE_URL 切换），生产部署走外接 |
| 7 | token/用量计量口径（AgentScope 侧是否有 usage 事件） | OBS 域计费/考核 | Sprint 1 探测时确认事件流字段 |
